# Описания экспозиций

Карточки показывают короткие предметные заметки: конкретные экспонаты, особенности коллекции, устройство музейного пространства и подтверждённые исторические детали. Текст сопровождается ссылками на страницы-источники и датой проверки. Он повторяется в подробной карточке; по содержимому можно искать, а переключатель «Только с описанием экспозиции» убирает записи без подтверждённых заметок.

В каталоге есть филиалы, дубли и записи кандидатов из справочников. Наличие общего сайта не означает, что у филиалов одинаковая экспозиция. Заметки привязываются к конкретным ID, при этом дубли той же площадки могут получать одинаковое описание. Если источник не описывает экспозицию, интерфейс не заменяет её выдуманным текстом.

## Обновление

1. `python scripts/collect_expositions.py --refresh` — ограниченный обход опубликованных страниц о коллекциях, экспозициях и истории. Помимо главной и найденных разделов запрашиваются страницы, на которые ссылаются уже принятые заметки. Результат сохраняется после каждого сайта, повторный запуск без `--refresh` продолжает незавершённый обход.
2. `python scripts/collect_exposition_browser.py` — дополнительный обход недоступных сайтов в изолированном публичном Chrome без профиля пользователя. Устанавливать новый браузер/зависимости автоматически не требуется. Неудачный дополнительный проход не стирает прежние сведения.
3. `python scripts/collect_expositions.py --prepare-only` — очередь `data/exposition-queue.json` и порции материалов в `data/cache/exposition/`. Их разбирают только внутренние агенты Luna. Фоновое расписание не обращается к внешним LLM API.
4. Luna записывает JSONL по доменам: `key`, `checked_at`, `processor: internal-luna`, `evidence_hash`, `records`. Запись площадки содержит `museum_ids`, `scope: venue`, `facts`: короткое перефразированное предложение `text`, точную непрерывную цитату-основание `quote`, исходный URL `source`. Для недостаточных материалов используются статусы `insufficient` / `not_museum`. Дополнительные официальные тексты сохраняются локально в `extra-*.json` с массивом `documents: [{source,text}]`.
5. `python scripts/apply_expositions.py --strict` — проверка ID, принадлежности сайта, хэша материала, исходной цитаты, длины и числа фактов. Ошибочные записи не публикуются. Обновлённая запись того же ключа заменяет предыдущую; `append_records: true` используется только для точечного дополнения отдельных площадок.
6. `python scripts/collect_expositions.py --prepare-only`, затем `python scripts/build_data.py` и `python scripts/verify_data.py` — сборка каталога и CSV. Проверка интерфейса: `python serve.py --port 8768`, `python scripts/verify_expositions.py`.

Утверждённые заметки хранятся в `data/exposition-notes.json` и входят в публичные JSON/CSV. Сырые ответы, основания и кэши остаются локальными. При изменившемся хэше или неудачной более поздней проверке прежняя заметка сохраняет старую дату и предупреждение, а источник попадает в очередь повторного разбора.

Полный периодический запуск `scripts/update_all.py --mode full` включает сбор текстов, браузерный дополнительный проход, валидацию и подготовку очереди. Ежедневный режим сохраняет существующие заметки и обновляет сведения об очереди. Принципиально новые/изменившиеся материалы требуют прохода агента Luna; выполнение по расписанию само не сочиняет описаний.

Новый код проверен тестами точного основания, неизвестного музея, другого сайта, области филиала и устаревания источника. Результаты браузерной проверки и снимки сохраняются в `artifacts/expositions/`.
