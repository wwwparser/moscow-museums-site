# Правила проекта «Музейный маршрут»

## Модель для обработки данных

По прямому указанию Юрия от 30 октября 2026 года для ВСЕЙ LLM-обработки этого проекта использовать только внутреннюю модель **Luna (`gpt-6-luna`)** в среде Codex.

- Классификация, извлечение тарифов и льгот, разбор текстов, проверка неоднозначных сведений и любая другая обработка с участием LLM выполняются внутренними агентами Luna.
- Вызовы внешних LLM API (DeepSeek, Dahl, OpenRouter, Gemini, DeepInfra и других), проверки их балансов и платные/бесплатные внешние замены запрещены. Эти правила имеют приоритет над общими рекомендациями о дешёвых внешних моделях.
- Не подменять внутреннюю Luna API-моделью с похожим названием. Если внутренний запуск недоступен в фоновом задании, сформировать очередь для Luna и явно отметить её в отчёте. Не переключаться на внешние API.
- Обычные Python-парсеры, HTTP-запросы к публичным сайтам музеев и Telegram, обработка PDF без LLM, валидация и сборка сайта продолжают работать без модели.
- Исключение по прямому запросу Юрия: визуальный редизайн этого сайта разрешено заказывать у ChatGPT через Browser Bridge с передачей публичных страниц и снимков. Это не разрешает внешние LLM API для обработки каталога, тарифов или персональных данных.
- Новые факты подтверждать текстом текущего официального источника; неподтверждённые данные не выдавать за свежие. При сбое сохранять прежние сведения с датой последнего успешного сбора и отметкой.

## Обновление и публикация

Основная команда — `python scripts/update_all.py --mode full --publish`; ежедневный режим — `--mode daily`. Перед публикацией выполнить проверки данных и затронутых сценариев интерфейса.
Сырой сбор и очередь для Luna остаются локально в `data/` и `data/cache/`. Не публиковать секреты, исходные кэши или ответы прежних LLM API. Публикация — GitHub Pages из `web/`.
